if Statements

An if statement checks if some expression is true and only executes teh code block if the answer is yes.

if 5 < 3:
    print("Five is smaller than three.")
print("Did I lie?")

Did I lie?

You can follow the block of code for an if statement with an else condition. This is another block that will only execute if the original statement was false.

if 5 < 3:
    print("Five is smaller than three.")
else:
    print("Five is NOT smaller than three.")
print("Did I lie?")

Five is NOT smaller than three.
Did I lie?

The expression 5 < 3 evaluates to False. The value is a boolean, a value that is only either True or False.

Functions

There are two ways you should think about functions. First, it changes the order that the code executes. When you call a function, control goes to the code block of the function and then it comes back with it is done.

Second, it takes an input and gives you an output. The output of a function is its return value. This is specified by the keyword return.

A function is defined and given a name using the def keyword. This is followed by a block. As always, a block is introduced by a colon, :.

def foo():
    return 3

print(foo())

3

The inputs to a function are called arguments. The arguments get assigned to local variables in the function that are called parameters and are specified when the function is defined. Here is an example where the parameter name is x. Inside the function, the argument will be called x, regardless of whether it had another name outside the function call.

def bar(x):
    return x + 1

y = 3
print(bar(y))

4

It's easy to confuse the words parameters and arguments. The difference is the same as the difference between variables and objects. The parameter is the variable (i.e., the name), but the actual object is the argument. Think of how hard it would be to write a useful function if you couldn't rename the arguments.

Names and Namespaces

You might call your mother "Mom", but someone else might call their mother "Mom". This means two people have the same name. To be able to know who you are referring to, you would need to add more information. In Python, names of things (like variables, function names, etc) are colleced into namespaces. Whenever you see a name with a dot in it, you are telling python where to look for the name you are trying to access. There are a couple common ways this happens, but perhaps the most common is when the name is attached to an object.

Read the following code.

class Foo:
    def __init__(self, x):
        self.x = x

x = 5
f = Foo(x)  
print(f.x)      

5

Even in this very simple example, you can see the name x is actually defined in three different namespaces. The line x = 5 assigns to the variable x. Because it didn't exist before this, the variable is created and the name is stored at the top level of the program. This is known as the global namespace. Then, the initializer for the class Foo has a parameter called x. This means that x is now defined as a local variable in this function. That is a namespace associated with a call to this function. Every time this function is called, it creates a namespace and add this variable to it. The third time the variable x is defined is in the assignment to self.x. The variable self has a namespace attached to it. Writing self.x indicates that we are creating the variable in the namespace of self. This is why the code self.x = x is referring to two different variables. One (on the right) is the local variable and the the other (on the left) is an attribute of self.

The pattern of taking an argument to the initializer and attaching it to the object being initialized is a very common pattern. The main reason is that you want to remember something. The local variables (the names) go away when the function returns. If an object no longer has a name, then the object will also go away. This is called garbage collection. By assigning a different name, self.x, to this object, the value of x will live on.

Wait. If the local variables go away, won't self also go away? Yes, but the object that self refers to doesn't go away. It is assigned to the variable f in the line f = Foo(). That's why we can access it lower by calling it f.x.
