A First Look at Classes

Python, we can usually use the word type and class interchangeably. We talk about the class of an object or the type of an object and generally, these are the same. In code, we use type to ask for the type and class to define a new type.

Here is the simplest definition of a class.

class Book:
    pass

b = Book()
print(type(b))

<class '__main__.Book'>

The keyword pass is a funny command that does nothing. I had to put it there, because, like functions, a class definition is followed by a block of code. If there aren't any indented lines after, it gives a syntax error.

In the code above, I defined a class called Book. I then created an instance of Book and assigned it to the variable b. When we printed the type of b, the name of its type is __main__.Book. That looks weird, but you already know that dot is used to identify a namespace. The special namespace __main__ is just Python's way of naming the main file of code that you are running right now.

Attaching Data to Objects

In Python, objects (usually) have their own namespace. Remember that we create new variable just by assigning values to them. When we write a name, we can also indicate the namespace where that name will live. So, we can specify an object as the namespace. This is like attaching data to the object, like with a sticky note.

class Book:
    pass

b = Book()
b.title = "Scaramouche"
b.author = "Rafael Sabatini"

print(f"{b.title} was written by {b.author}.")

Scaramouche was written by Rafael Sabatini.

You can maybe see why this is very useful. If I have a function and I pass it a book (as an argument), I also pass the namespace, and therefore get all the data that comes with it.

class Book:
    pass

def info(book):
    print(f"{book.title} was written by {book.author}.")

b = Book()
b.title = "Moby Dick"
b.author = "Herman Melville"

info(b)

Moby Dick was written by Herman Melville.

Notice that the name of the variable in the function is different from the name of the variable outside the function. This is related to variable_scopes_in_python. Calling the function with argument b then assigns the parameter book to refer to whatever object b refers to.

If you try to use a variable that doesn't exist, you get an error, as you might expect. It might look like this.

class Book:
    pass

def info(book):
    print(f"{book.title} was written by {book.author}.")

b = Book()
b.title = "War and Peace"

info(b)

Traceback (most recent call last):
  File "<stdin>", line 10, in <module>
  File "<stdin>", line 5, in info
AttributeError: 'Book' object has no attribute 'author'

The error shows that when we called info, we then called print and tried to access a variable called author. The actual error is AttributeError: 'Book' object has no attribute 'author'. So, the data that we define on an object is called an attribute.

Initializing Objects

When creating the Book instance, we used parentheses. In this way, it looks like a function. Behind the scenes, there is a function that Python calls when a new object is created. It's called the initializer. Usually, when you design your own class, you also design an initializer. This is nice because it will allow us to make sure that the right attributes are defined. The name of the initiallizer function has to be __init__. These double underscore names are sometimes called dunder methods ("double underscore" has too many syllables.) They are also called magic methods. Usually, you don't call magic methods directly, you let them get called automatically by some standard Python action. In our case, the initializer is called when a new object is created.

Here is our example with an initializer.

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

def info(book):
    print(f"{book.title} was written by {book.author}.")

b = Book("War and Peace", "Leo Tolstoy")

info(b)

War and Peace was written by Leo Tolstoy.

Here is how Python executes this code:

  • It first defines a new class called Book.
  • It adds an initializer to the class.
  • It then defines a function called info.
  • A new Book object is created.
  • The new Book object is passed to the initializer (as the first parameter, self) along with the other arguments "War and Peace" and "Leo Tolstoy".
  • The title and author parameters are added as attributes to self. Notice that title is different than self.title because they are in different namespaces.
  • The new book object is assigned to the variable b.
  • The info function is called on b.
  • The title and author of the book are printed to the screen.

Let's add a Method

Our info function is a natural choice to be rewritten as a method.

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def info(self):
        print(f"{self.title} was written by {self.author}.")

b = Book("Hop on Pop", "Dr. Seuss")

b.info()

Hop on Pop was written by Dr. Seuss.

Three amin things have changed.

  1. We indented the function, so now it is inside the class block.
  2. We changed teh name of the parameter from book to self. We didn't have to do this, but it is considered completely standard to always use self for the first parameter of a method.
  3. We changed how we called the function. Instead of writing info(b), we call b.info().

This last difference seems very small, but it's actually pretty amazing. Remember how we passed b to our info function and the data attached to b came with it automatically. By having methods, we can pass b to a function and all its methods come with it. Usually, this would create problems with names because we would have to make sure that the names of the functions were available inside the function. Now, they just come with the object.

This is main point of defining classes and methods. It allows us to package up both data and the functions that operate on that data (i.e. methods) together into a single thing (an object).

Another Example

I think the first time you put multiple mathematical things together into a single thing was when you learned about coordinates in the plane. A point in the plane can be thought of as a pair of numbers, an x coordinate and a y coordinate.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def to_the_left_of(self, other):
        return self.x <= other.x

    def higher_than(self, other):
        return self.y >= other.y

    def __str__(self):
        return f"({self.x}, {self.y})"

    def add(self, other):
        return Point(self.x + other.x, self.y + other.y)

a = Point(2,3)
b = Point(3,2)
c = a.add(b)

print(f"a = {str(a)}, b = {str(b)}, c = {str(c)}")
assert(a.higher_than(b))
assert(a.to_the_left_of(b))

a = (2, 3), b = (3, 2), c = (5, 5)

Here we used another magic method: __str__. This is the method that you define to tell Python how to write the object as a string. Python calls this method when you try to turn something into a string with expressions like str(a).
