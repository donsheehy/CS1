What's in a file?

Most people are comfortable with the idea that data is stored as binary. They imagine the computer full of zeros and ones, but when we open a file or run a program that's stored in a file, these zeros and ones have to be interpreted to mean something. That means we have to come up with a convention to interpret the binary. This will be different for different types of files, but we'll focus on the two that are most important to us: text files and programs. But first we'll talk about names.

File Names

A file name is a string. It is also how you refer to the file from the command line, so names show up constantly when you are navigating the file system. Many file names have a period followed by a sequence of characters called the extension. We have seen this already in examples like hello.py. In this case, the .py is the extension. It's important to note that the extension is just a hint about what kind of file you are looking at. It might not be the type of file you think it is. I could write a text file and give it a .pdf extension but that doesn't make if a PDF. If you try to open that file, your computer might try to open it with Acrobat Reader or some similar program and it will fail.

Filenames are case sensitive. file.txt and filE.txt are not the same.

Never use spaces in file names. It is allowed, but it is a bad idea.

Text Files

A text file contains just text. There's no fonts, there's no bold, italic, or other formatting, no pictures; it's just a sequence of letters. The text file is just a string that has been saved to disk. We use text files for lots of different things. For example, a Python program is just a text file.

print('I am text.')

I am text.

The code that generates this website and also probably your text editor will change the colors of the font to make it easier to read based on its knowledge of the Python programming language. But the file that contains this program will just be a sequence of characters.

Here is a script that will make this text file for us.

printf '%s\n' "print('I am text.!')" > im_text.py



Now, we can use python to open the file.
We can print the data one byte at a time.
A byte is 8 bits.
For each byte of data, we give the letter and the binary.
The chr(byte) turns a number into a letter.
The formatting byte:08b formats that numebr using eight bits.


# Open the file and read the data.
with open('im_text.py', 'rb') as f:
    data = f.read()

# Loop over the bytes
for byte in data:
    # print the byte as a letter and in binary.
    print(f"{chr(byte)}: {byte:08b}")

Programs


You might think that the file containing the Python code is a program. In some sense, that is true, but it's not the program from the perspective of the computer. For the computer, a program will be a series of instructions to execute.
The program that we run to execute our code is the Python program. That's why from the terminal we write python or python3 followed by the name of the file with our code.
To get a sense of what these commands look like, I've written a Hello World program in a different programming language called C.
You have seen a pile of Python versions of that same program in hello_world_variations.


#include <stdio.h>

int main(){
    puts("Hello, World!");

    return 0;
} 



You'll notice that it's a little more complicated than Python.
I won't tell you what all the lines do, but I'll point out that this program just prints Hello, World! exactly as you might hope.


There is a program called a compiler that takes this code and turns it into an executable program.
That is, it converts it into individual instructions that can be executed by the processor.
