Lists

Making a List

primes = [2, 3, 5, 7, 11]
print(primes)
print(f"{len(primes)=}")

[2, 3, 5, 7, 11]
len(primes)=5

A list is one name for several values, kept in order. You write one with square brackets around the items and commas between them. That is a list literal, the same idea as the string literals in strings_and_print. It literally tells you what the list is. The len function reports how many items are in it.

A list can hold any values you like, including a mix of types.

mixed = [1, "two", 3.0]
empty = []
print(f"{mixed=}")
print(f"{empty=} {len(empty)=}")

mixed=[1, 'two', 3.0]
empty=[] len(empty)=0

The list with nothing in it is the empty list. It looks useless. It is where most lists start.

Indexing

names = ["Ada", "Alan", "Grace"]
print(names[0])
print(names[2])

Ada
Grace

Every item has a position in the list, called its index. Counting starts at zero, so names[0] is the first item and names[2] is the third. Putting brackets after the list to get one item out is called indexing.

Key Idea: The first item is at index 0, so in a list of length n, the last item is at index n - 1.

You don't have to do that subtraction yourself. Negative indices count back from the end.

names = ["Ada", "Alan", "Grace"]
print(f"{names[-1]=}")
print(f"{names[-2]=}")

names[-1]='Grace'
names[-2]='Alan'

Asking for a position that doesn't exist is an error.

names = ["Ada", "Alan", "Grace"]
print(names[3])

Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
IndexError: list index out of range

An IndexError means you ran off the end of the list. There are three items, so the largest legal index is 2. When a program crashes this way, the usual cause is an off by one error, and the usual culprit is forgetting that the counting starts at zero.

Storing Things in a List

names = ["Ada", "Alan", "Grace"]
names[1] = "Alonzo"
print(names)

['Ada', 'Alonzo', 'Grace']

An index can go on the left of an assignment as well as on the right. On the right, it reads the item at that position. On the left, it replaces it. The list stays the same length, and the old value is gone for good.

Key Idea: Reading an item and storing an item look identical. Which one you get depends on which side of the = the brackets are on.

This is the first thing we have seen that you can change in place. Such a value is called mutable. Strings are not mutable.

s = "hello"
s[0] = "H"

Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
TypeError: 'str' object does not support item assignment

The TypeError says that a string does not support item assignment. Once a string exists, its characters are fixed. To "change" a string, you have to build a new one and assign that. Look back at variables_and_assignment and notice the difference. There, we changed which value a name referred to. Here, we changed the value itself, and every name referring to that list sees the change.

You can only store into a position that already exists.

names = ["Ada", "Alan", "Grace"]
names[3] = "Barbara"

Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
IndexError: list assignment index out of range

That is an IndexError again, this time complaining about list assignment. Assignment is not a way to make a list longer. For that, you need append.

Growing a List

squares = []
squares.append(1)
squares.append(4)
print(f"{squares=}")

squares=[1, 4]

The append method adds one item to the end of a list. A method is a function that belongs to a particular value, and you call it by writing a dot after that value. So it's squares.append(4) and not append(squares, 4).

The usual pattern is to start with an empty list, append inside a loop, and let the list grow to whatever size you need. Loops get their own note, for_loops.

squares = []
for i in range(5):
    squares.append(i * i)
print(f"{squares=}")

squares=[0, 1, 4, 9, 16]

Now look carefully at what append gives back.

squares = [1, 4, 9]
result = squares.append(16)
print(f"{squares=}")
print(f"{result=}")

squares=[1, 4, 9, 16]
result=None

The list grew, and result is None. That is because append changes the list you called it on and returns nothing. So squares.append(16) belongs on a line by itself. If you write squares = squares.append(16), you throw the list away and leave squares referring to None.

I have found that this one costs students an hour of debugging at least once. You already know the slogan from strings_and_print: printing is not returning. Here is the sequel: appending is not returning.
