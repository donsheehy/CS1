Navigating the File System from the Command Line

The File System Is a Collection of Places

Think about where a physical piece of paper might live. It's in a folder, and that folder is in a drawer, and that drawer is in a filing cabinet, and the cabinet is in a room. To find the paper again, you'd describe all of that: cabinet, drawer, folder. Each place is nested inside a bigger place.

Your computer's file system works the same way. It's a giant collection of places, and every place (except one) sits inside exactly one other place. A place that holds other places is called a directory (also called a folder). Nothing floats around loose. Every file and every directory has a parent, one specific place that contains it, and that parent has its own parent, and so on.

This idea, a thing containing smaller things of the same kind, is called nesting (see Nesting for other places it shows up). When you draw out a nested structure like this, with places branching into smaller places, you get a shape called a tree.

At the very top of the tree is one place that isn't inside anything else, the root. On Mac and Linux (and in Git Bash on Windows), the root is written as a single slash: /. Every other place, no matter how deeply nested, can be reached by starting at root and stepping down into directory after directory.

A file is a place with no places inside it, a document, a program, a picture, anything with actual content in it. A directory is the opposite: it doesn't hold content itself, it holds other files and directories.

You have your own corner of this tree called your home directory. It's written as ~ (a tilde), and it's where you land whenever you open a fresh terminal. Everything you create for this class will live somewhere under ~.

Because every place has exactly one parent, there is exactly one route from root down to any given file or directory. Writing down that route, step by step, gives you the place's path.

Key Idea: The file system is one giant tree, a collection of nested places, and every file's location can be written as a path from the root.

The command line is how you walk around that tree without a mouse.

Where Am I: pwd

The shell always remembers where you're currently standing in the tree. To ask it, use pwd, short for print working directory.

pwd

/Users/ada/cs1

That output is a path. Read it left to right: start at root /, go into Users, then ada, then cs1. That's four stops on the tree, and you're standing at the last one.

Look Around: ls

Now that you know where you are, you probably want to know what's there.

ls

notes.md   photos   scripts

This lists everything sitting in your current directory. Some of those are files (notes.md), and some are directories (photos, scripts), but plain ls doesn't tell you which is which.

Try it in a brand new, empty directory.

ls

Nothing prints. An empty directory isn't an error, it's just empty, so there's nothing to list.

Every directory secretly contains two entries you didn't put there, . and ... Plain ls hides them. To see everything, including hidden files (whose names start with a dot), add the -a flag.

ls -a

.   ..   notes.md   photos   scripts

What are . and ..? They're not files you made. They're built-in shortcuts every directory has, and they're the key to moving around.

Move Around: cd

To walk to a different spot in the tree, use cd, short for change directory.

cd scripts
pwd

/Users/ada/cs1/scripts

One command, and your working directory moved one stop deeper into the tree.

Remember that mysterious .. from ls -a? It means "the directory one level up." So to go back where you came from:

cd ..
pwd

/Users/ada/cs1

.. is a relative shortcut. It always means "my parent," no matter where you are in the tree. . means "here, this exact directory I'm already in." You won't use cd . much, but you'll see . again once you start running scripts and copying files.

No matter how lost you get, you can always teleport home:

cd ~
pwd

/Users/ada

Absolute and Relative Paths

You've actually already used both kinds of paths without naming them.

A relative path is directions from where you're currently standing, like cd scripts or cd ... It only makes sense relative to your current position in the tree.

An absolute path is the full address starting from root, like /Users/ada/cs1/scripts. It means the same thing no matter where you were standing when you typed it.

cd /Users/ada/cs1/scripts
pwd

/Users/ada/cs1/scripts

That command would have worked identically whether you started at home, inside photos, or anywhere else. That's the whole point of an absolute path: it doesn't care where you started.

Key Idea: A relative path is directions from here. An absolute path is directions from root, and root never moves.

Making a New Folder: mkdir

To add a new branch to the tree, use mkdir, short for make directory.

mkdir homework
ls

homework   notes.md   photos   scripts

A new, empty directory just appeared, right where you were standing. You can cd into it immediately.

cd homework
pwd

/Users/ada/cs1/homework

That's the whole loop you'll repeat constantly this semester: pwd to see where you are, ls to see what's around you, cd to move, mkdir to build new places to move to.

(If you're on Windows and haven't set up a Unix-style shell yet, see Getting Started with Git Bash before trying these commands.)
