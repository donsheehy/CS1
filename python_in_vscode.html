Running Python in VSCode

VSCode is a text editor. Python is a program that runs your code. They are two separate things, and this whole setup is just about getting them into the same window so you can write a program and run it without switching applications.

There is more than one way to run Python from VSCode. This note covers the simplest one, where you type the command yourself.

Install Python

Go to https://www.python.org/downloads/ and run the installer for the latest version.

On Windows, the first screen of the installer has a checkbox that says Add python.exe to PATH. Check it. This is the one step people skip, and if you skip it, the terminal will not be able to find Python later. Everything else can stay at its default.

On a Mac there is no such checkbox and you do not need one.

Install VSCode

Go to https://code.visualstudio.com/ and install it. The defaults are fine.

You do not need any extensions yet. Microsoft publishes a Python extension that adds a Run button, and it is genuinely useful, but it is not required and it hides some of what is going on. Wait on it.

Open a Folder, Not a File

Make a folder somewhere for this class. Call it cs1. Then in VSCode, choose File → Open Folder and pick it.

The folder now shows up in the Explorer sidebar on the left, empty for the moment. VSCode is built around folders rather than loose files, and, more importantly for us, the terminal you are about to open will start inside whatever folder you opened.

Key Idea: Open the folder at the start of every session, not the file. Everything else stays in the right place because of it.

Make a File

In the Explorer sidebar, hover over your folder name and click the new file icon. Name it hello.py. The .py at the end is what marks it as Python.

Type this in:

print("Hello, World!")

Now save it with Ctrl-S, or Cmd-S on a Mac. VSCode does not save on its own. If the tab shows a dot instead of an x, the file has unsaved changes and running it will run the old version. This will happen to you at least once.

Open the Terminal

Choose Terminal → New Terminal from the menu.

A panel opens at the bottom of the window with a prompt in it. That prompt is a shell, the same kind of shell described in Navigating the File System. It is not part of Python and it is not part of VSCode. It is the program your operating system already uses to run other programs, borrowed and stuck into the bottom of your editor so you don't have to leave.

Check where it thinks it is:

pwd
ls

You should see the path to your cs1 folder, and hello.py in the listing. If you do, the folder you opened and the folder the shell is standing in are the same, and the next step will work.

Run the Program

python hello.py

The output appears on the next line:

Hello, World!

That is the entire cycle. Edit, save, run. You will do it a few thousand times this term.

Notice what the command is made of. The word python is the name of a program, the one you installed in the first step. hello.py is an argument, a piece of information handed to that program when it starts, in this case the name of the file you want it to read. The shell finds the program, hands it the argument, and gets out of the way. There is nothing special about hello.py here, it is just text you typed.

On a Mac, python by itself may say command not found. Use python3 instead. On Windows, if typing python opens the Microsoft Store, try py instead. Whichever one works for you, use that one from now on.

One more thing that will save you a lot of typing. Press the up arrow in the terminal and the previous command comes back. So after the first run, the cycle is: edit the file, Ctrl-S, click the terminal, up arrow, Enter.

When It Doesn't Work

command not found or is not recognized. The shell cannot find Python. On Windows this almost always means the PATH checkbox was missed, so reinstall and check it. Otherwise, try python3 or py.

can't open file 'hello.py' or No such file or directory. Python started fine, but the shell is standing in a different folder than your file. Run ls to see where you are, and cd your way over.

The prompt turned into >>>. You ran python with no file name, so you are inside Python itself, typing code one line at a time. This is the interactive interpreter, and it is useful, but it is not what we want right now. Type exit() and press Enter to get back to the shell.

Nothing printed, or you see old output. The file was not saved. Ctrl-S, then run it again.

A SyntaxError pointing at a quotation mark that looks fine. You pasted the code from a word processor or a web page, and the quotes came along as curly typographic quotes rather than the straight ones Python expects. Retype the line in VSCode.

What's Next

Once this is routine, two things are worth adding. The Microsoft Python extension gives you a Run button in the top right corner that does exactly what you just typed, plus autocomplete and error underlining as you write. And you can start putting real code in the file, beginning with Strings and Print.
