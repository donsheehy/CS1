Working with Files

Early on, we used the input() function to take input from a user. This is nice and interactive, but it is also a pretty slow way to get input into a program. For some examples, we wanted to look at large inputs. In those cases, it makes sense to have a program that opens the file and reads it in. You'll notice that we did this in examples like our distribution_example. In this note, I'll work through the techniques and the mental models for working with files.

Open and Close

When a program wants to access a file, it technically asks the operating system. Recall that the operating system is the main program that organizes and runs other programs on your computer (see computer_architecture).

Python asks the operating system for access to a file by opening the file. It is then expected that your program will also close the file.

You can think of this file access as a phone call. When you open the file, it's like you making the call. Then, you can read through the file in order. When you don't need the file anymore, closing the file is like hanging up the phone.

Here is a very simple program that opens a file, reads the first line and closes it again.

f = open("working_with_files.md", "r")
print(f.readline())
f.close()

Let's walk through the pieces of this program. The first line calls a standard Python function called open. There are two arguments. The first is a filename. In this case, we passed the name of the markdown source for these notes. The second argument is a string "r". This is how we tell the operating system that we want to open the file in order to read it. ("r" for read).

The open function returns an object that we can use to access the file. We assigned it to a variable called f. Then, we called readline method on f to read a line from the file. We also printed that line. Finally, we close the file by calling the close method.

There are methods for reading from the file. For example, the read method reads the whole file into a string. You wouldn't want to do this if it's a really huge file.

You can also iterate over the lines of a file.

f = open("working_with_files.md", "r")

for line in f:
    # Check if the line is a heading.
    # (headings starts with a `#` sign)
    if line[0] == '#':
        print(line)

f.close()

How to never forget to close the file

The way I have been showing file commands, I was always manually closing the file. There is a standard alternative to this pattern. It is so standard that good Python programs almost never call the close method themselves. The syntax is a little different than you might expect.

with open("working_with_files.md", "r") as f:
    for line in f:
        # Check if the line is a heading.
        # (headings starts with a `#` sign)
        if line[0] == '#':
            print(line)

This is the same program as above, but it uses the with keyword. All of the code that works with the file is indented into a block. The idea is simply that after this block of code, the file gets automatically closed.

The with keyword introduces something called a context manager. We won't go into detial on how these work, but the idea is that the block has a context and there is some setup and cleanup that happens for this context.

The other new aspect of this syntax is the as keyword. This is how we name the object that is controlling the context.

Writing to files

So far, we have only read from files. Writing uses the same open function and the same with block, but with a different second argument. Here is a program that writes a short shopping list to a file.

with open("shopping_list.txt", "w") as f:
    f.write("eggs\n")
    f.write("milk\n")
    f.write("bread\n")

with open("shopping_list.txt", "r") as f:
    print(f.read())
Output 
eggs
milk
bread

This program has two with blocks. The first one writes to a file and the second one reads it back so we can see what happened.

To write to a file, we open it with the string "w" as the second argument. This is called write mode ("w" for write). If the file does not exist yet, opening it in write mode creates it.

The write method takes a string and puts it into the file. Notice that every string we wrote ended with \n. That is the newline character from strings_and_print. Here is what happens if we leave it out.

with open("shopping_list.txt", "w") as f:
    f.write("eggs")
    f.write("milk")
    f.write("bread")

with open("shopping_list.txt", "r") as f:
    print(f.read())
Output 
eggsmilkbread

Everything runs together on one line. The print function adds a newline at the end for you, but the write method does not. It puts exactly the characters you give it into the file, and nothing else.

Key Idea: write does not add a newline. If you want separate lines, you have to write the \n yourself.

The write method also insists on getting a string.

with open("numbers.txt", "w") as f:
    f.write(42)
Output 
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
TypeError: write() argument must be str, not int

This gives a TypeError. The print function will happily print a number, but write will not convert it for you. The fix is to make the string yourself, either by casting with str or by using an f-string.

with open("numbers.txt", "w") as f:
    for i in range(5):
        f.write(f"{i} squared is {i**2}\n")

with open("numbers.txt", "r") as f:
    print(f.read())
Output 
0 squared is 0
1 squared is 1
2 squared is 4
3 squared is 9
4 squared is 16

Write mode erases the file

There is one more thing to know about write mode, and it is the one that bites people.

with open("shopping_list.txt", "w") as f:
    f.write("eggs\n")
    f.write("milk\n")

with open("shopping_list.txt", "w") as f:
    f.write("bread\n")

with open("shopping_list.txt", "r") as f:
    print(f.read())
Output 
bread

The eggs and the milk are gone. When you open a file in write mode, the first thing that happens is that the file is emptied. It does not matter what was in it before. Python does not ask if you are sure.

Key Idea: Opening a file with "w" erases everything that was already in it.

Appending to files

Often you want to add to a file without losing what is already there. For that, there is a third mode.

with open("shopping_list.txt", "w") as f:
    f.write("eggs\n")
    f.write("milk\n")

with open("shopping_list.txt", "a") as f:
    f.write("bread\n")

with open("shopping_list.txt", "r") as f:
    print(f.read())
Output 
eggs
milk
bread

This is the same program as the last one, except the second open uses "a" instead of "w". This is called append mode ("a" for append). To append means to add something to the end. Now the bread goes after the eggs and milk, and nothing is erased. Like write mode, append mode will create the file if it does not exist yet.

A common use for appending is a log file. A program adds a line to the log every time something happens, so you can look back later and see what it did.

with open("log.txt", "w") as f:
    f.write("Log started\n")

for score in [88, 92, 75]:
    with open("log.txt", "a") as f:
        f.write(f"Recorded a score of {score}\n")

with open("log.txt", "r") as f:
    print(f.read())
Output 
Log started
Recorded a score of 88
Recorded a score of 92
Recorded a score of 75

Notice that the file gets opened and closed again on every pass through the loop. Because we used append mode, nothing is lost each time it is reopened. If we had used "w" inside the loop, only the last score would be left.
