Using pip

What pip Is

Python comes with a lot built in, but not everything. Other people have written thousands of useful packages (also called libraries) that you can add to your own Python. The tool that downloads and installs them is called pip.

Most packages live on a website called the Python Package Index, or PyPI, at pypi.org. When you ask pip for a package, it looks it up there, downloads it, and puts it where Python can find it.

You run pip from the Terminal, not from inside a Python program.

Checking That You Have It

First, make sure pip is there. Type this in the Terminal:

pip --version

You should see a version number and a path to the Python it belongs to. On a Mac, the command is usually pip3, for the same reason you type python3 instead of python (see homebrew_on_mac).

Installing a Package

Say you want the requests package, which makes it easy to fetch web pages. If you try to use it before installing it, Python complains:

ModuleNotFoundError: No module named 'requests'

A ModuleNotFoundError almost always means "you haven't installed this yet." So install it:

pip install requests

pip prints a few lines as it downloads things, and ends with something like Successfully installed requests-2.32.3. You may notice it installed a few other packages too. Those are dependencies, packages that requests itself needs. pip handles them for you.

Now import requests works in your programs.

A Few Other Commands

Here are the handful of pip commands you'll actually use.

Command What it does
pip install X Install the package X
pip install --upgrade X Update X to the newest version
pip uninstall X Remove X
pip list List everything installed
pip show X Show details about X

The "Externally Managed" Error

If you installed Python with Homebrew (or on some Linux systems), you may see this when you try to install something:

error: externally-managed-environment

This is Python protecting itself. Homebrew wants to manage that copy of Python, and doesn't want you mixing your own packages into it.

The fix is a virtual environment. A virtual environment is a private copy of Python that lives in a folder inside your project. You can install whatever you like there without disturbing anything else.

python3 -m venv .venv
source .venv/bin/activate

The first line creates the environment in a folder called .venv. The second line activates it. Your Terminal prompt should now start with (.venv). While it is active, pip install puts packages into .venv, and python3 uses them.

On Windows with Git Bash, the second line is source .venv/Scripts/activate instead.

When you're done, type deactivate. Next time you work on the project, cd into its folder and run the source line again. In VS Code, you can also pick the .venv interpreter so it runs your code with the right packages (see python_in_vscode).

Troubleshooting: Installed, but Still ModuleNotFoundError

Sometimes pip says Successfully installed, but your program still can't find the package. The usual cause is that your computer has more than one Python on it. pip and python3 are separate commands, and they can belong to different copies of Python. pip installed the package into one, and your program is running with the other.

To check, run these two commands and compare the paths they print:

pip --version
python3 -m pip --version

The second one asks python3 for its own pip. If the paths are different, you've found the problem. Install with the second form instead:

python3 -m pip install requests

A virtual environment also fixes this, since activating it makes pip and python match.

If your code runs from the Terminal but fails when you press Run in VS Code, it's the same problem in a different place. VS Code is using a different Python than your Terminal. Pick the matching interpreter in VS Code (see python_in_vscode).
