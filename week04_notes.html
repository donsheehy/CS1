Lists, Objects, and Methods

What is an object?

Pretty much everything that you might call a "thing" in Python is an object. Anything that you store in memory and can assign a name to is an object. The number 5 is an object of type int for integer. All numbers are objects. Strings are objects. Even functions and types are objects.

print(type(str))

<class 'type'>

Every object has three parts.

  1. It has an identity. This is a way to distinguish this object from any other object. In practical terms, this is usually a number that indicates where in the memory the object is stored.

  2. It has a type.

  3. It has a value. This is the actual data that is stored in memory.

The difference between the value and the identity.

Two objects can have the same value, but different identities.

X = [1,2,3]
Y = [1,2,3]

print(f"{X is Y = }")
print(f"{X == Y = }")

X is Y = False
X == Y = True

What is a method?

Here is a program that is only for demonstration purposes. If you wrote this in a job, you would get fired.

L = [1,3,5,7]
list.append(L, 9)
print(L)

[1, 3, 5, 7, 9]

The reason you would get fired is that you should have instead written the following code.

L = [1,3,5,7]
L.append(9)
print(L)

[1, 3, 5, 7, 9]

It looks basically the same. It does the same thing. It (arguably) makes less sense. It might even be infinitesimally slower. So why is it better?

Let's instead start with how it is different.

list.append is the name of the function that appends an object to a list. It has a dot in the name to indicate the namespace list. A namespace is just a set of names. We use namespaces so that we can distinguish between different objects with the same name. For example, you might have some other type of object that also has an append function. Here, we know exactly which one we mean.

L.append is also a function, but it's a special kind of function called a method. When we write L.append(9), python looks in the namespace L for an append function. It doesn't find one. Then it looks in the namespace of the type of L. In this case, the type is list. It does find the list.append function. It then passes L as the first argument to that function. So, in this case, L.append(9) resolves to a function call list.append(9). So, why write it this weird way?

The key is that we are allowing the list L to decide how appending works. If it is of type list, then maybe it will delegate appending to that function. But maybe, it's a different kind of object with a different way to append. In this case, we want to trust it to do the right thing for whatever kind of object it is.

Methods are functions that operate on objects. There are all kinds of methods on objects that you have already seen. For example, even int has some special methods.

x = 5
num_bits = x.bit_length()
print(f"It takes {num_bits} bits to represent {x}.")

It takes 3 bits to represent 5.

In this case, there are no arguments (inputs) needed for the bit length, so the parentheses are empty. It is a method on x, so x is an implicit argument. When we write our own methods, these implicit arguments will be made explicit.

If you have an object and the type of that object has a method. You can call that method on that object. So, the following code works, but maybe isn't recommended. (I had to add parentheses so Python wouldn't think I was using the period as a decimal point).

num_bits = (12).bit_length()
print(f"It takes {num_bits} bits to represent 12.")

It takes 4 bits to represent 12.

Taking Notes

Markdown

I write my notes in VSCode. I write them as plain text files with a .md extension. This stands for markdown.

Markdown was invented to be easy to read, but also easy to translate into html, the language of web pages.

The idea is is simple. We use special characters to indicate certain kinds of formatting. So, if I put asterisks around some text, that's how I indicate that it should be italic. If I put double asterisks around text it will be bold. If I start a line with a pound sign (i.e. a hash symbol), it will be a header. The level of the header is indicated by the number of hashes.

There are several other standard shortcuts you can look up a cheat sheet on how to write Markdown. There are many of these available on the internet.

Code Blocks

Markdown lets you indicate a code block using triple backticks. That's the key in the upper left corner of your keyboard next to the 1. You can also include what programming language you're using. And that will help some programs to figure out how to change the colors for the syntax of your language. Here's an example in Python.

<pre>

for i in range(5):
    print("Hello, World!)

</pre>

Previewing

In VSCode, you can open the built in markdown previewer to see the rendered version of your file. It is really a web browser showing the markdown as html.

In some of the examples in this note, I am using a more powerful previewer called Markdown Preview Enhanced. This allows me to run the code blocks in the notes and see the output in the preview.

SVGs

One of the standard types of images that you will find on the web is called an SVG. This stands for Scalable Vector Graphics. It is human-readable. It uses a tag-based markup system similar to html.

Writing SVGs in Python

To make these figures, I am using a Python package called svg.py. A package is some code (usually, code written by someone else) that you can download and use. A common way to install other packages is using a tool called pip. To install teh svg package, you would use the following command in a terminal.

pip3 install svg.py

Here is a simple example of using the code.

from svg import SVG, Circle

a_dot = Circle(cx=100, cy=100, r=10)
another_dot = Circle(cx= 200, cy = 50, r=10)

my_image = SVG(elements=[a_dot, another_dot]) 

print(my_image)

Here is an image as a text file. It's the same as above, except I added some newlines so that it wraps nicely.

<svg xmlns="http://www.w3.org/2000/svg">
    <circle cx="100" cy="100" r="10"/>
    <circle cx="200" cy="50" r="10"/>
</svg>
