Variables and Assignment

Names and Values

course = "CS1"
students = 30
print(course, students)

CS1 30

The = sign is the assignment operator. It gives the name on the left to the value on the right. A variable is a name that refers to a value. Here, course refers to the string "CS1" and students refers to the integer 30.

We first met variables in strings_and_print. Think of a variable as a label stuck on a value, not a box that holds it.

The Right Side Comes First

x = 3 * 4
x = x + 1
print(x)

13

Python evaluates the whole right side first. Only then does it assign the result to the name on the left. So x = x + 1 takes the current value of x, adds one, and makes x refer to the result. This is called updating a variable. For more on how expressions get evaluated, see arithmetic_and_evaluation.

Key Idea: = is not an equation. Evaluate the right side, then assign.

Shortcuts for Updating

score = 10
score += 5
print(f"{score=}")
score *= 2
print(f"{score=}")
score -= 1
print(f"{score=}")

score=15
score=30
score=29

The line score += 5 means score = score + 5. These are the augmented assignment operators. Every arithmetic operator has one: +=, -=, *=, /=, //=, %=, and **=.

Assigning One Variable to Another

a = 7
b = a
a = 100
print(f"{a=} {b=}")

a=100 b=7

The line b = a makes b refer to whatever a refers to right now, which is 7. It does not tie b to a forever. When a gets a new value, b keeps the old one.

Using a Name Before Assigning It

total = subtotal + 5

Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'subtotal' is not defined

The result is a NameError. Python runs your program top to bottom, and subtotal has not been assigned yet. A variable only exists after the line that assigns it has run.

Values Have Types, Names Don't

x = 42
print(f"{x=} {type(x)=}")
x = "forty-two"
print(f"{x=} {type(x)=}")

x=42 type(x)=<class 'int'>
x='forty-two' type(x)=<class 'str'>

The type belongs to the value, not the variable. The same name can refer to an int and later to a str. Python allows it, but I have found it usually makes code harder to follow.

Naming Rules

2nd_place = "silver"

File "<stdin>", line 1
    2nd_place = "silver"
    ^
SyntaxError: invalid decimal literal

That name breaks a rule, so you get a SyntaxError. Here are the rules.

  • Use only letters, digits, and underscores.
  • Don't start with a digit.
  • Names are case-sensitive, so total and Total are different variables.
  • Don't use a keyword, like if, while, or True, as a name.

By convention, Python programmers write names in snake_case, lowercase words joined by underscores, like max_guesses. Pick names that say what the value means. max_guesses beats mg.
