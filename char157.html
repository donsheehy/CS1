The Character 157 Mystery

In class, we wrote a short Python program as follows:

for i in range(256):
    print(f"{i} = {chr(i)}")

The program did not work as expected. It did something quite strange in that it crashed but didn't give an error message. Almost always when a Python program crashes, you get an error. In this case, it just stopped.

I love when stuff like this happens.

It's completely normal, and expected that we will write programs that don't work as expected. The important thing is to cultivate the right attitude.

What we got is not a problem, it's a mystery, and mysteries are fun.

In this case, a little internet search revealed the answer, but it is interesting to see how we could have discovered the answer ourselves. One idea would be to look up what character 157 or 158 really is. We would find that it is a non-printable character. However, there is no problem with storing such a character to a file. We can do this and then look at the file in VSCode. It is interesting to see the result.

Here is a wonderful trick. We will save the program as all_the_characters.py. The usual way we would run this program is to type the following command in the terminal.

python3 all_the_characters.py

This is the version that stops printing around 157. Instead, we will run the command as follows.

python3 all_the_characters.py > characters.txt

The difference is that the greater-than symbol directs all the output to a file instead of printing it to the screen. When we open the file, we might first see a warning that it's a binary file. That's okay, we can open it. We see all the characters are there. There is a blank for some of the characters and maybe some strange placeholders for some of the other characters, but for the most part, everything is there that is supposed to be there.

So, what crashed our program?

We know that the python code is valid and can run and send it's output to a file, but it couldn't print it in the terminal. This is the hint. The terminal killed our program. No error message. No warning. It saw a program attempting to print non-printing characters to the screen and it immediately killed the program.

This answer is strange. Other programs can print these characters to the terminal, or they manage to suppress them. For example, we can print the contents of characters.txt in the terminal by running the following command.

cat characters.txt

The cat command prints the contents of a file. No, there isn't a dog command, but there is a man command. You can run man cat and see the manual for the cat command. If you run cat man, you will get an error.

One note on vacabulary: when I say that the terminal killed our program, this is actually the technical term for stopping a program from the outside. You can run man kill if you are interested, but you will likely get a weird error if you run kill man.
