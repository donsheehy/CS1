Processor, Memory, Storage, and I/O

Four Parts

Almost every computer you will ever meet, from the phone in your pocket to a room full of servers, is built out of four kinds of parts.

  • The processor does the work.
  • The memory holds what is being worked on right now.
  • The storage keeps things around after the power goes off.
  • The input/output devices, usually shortened to I/O, connect the machine to the world.

That is the whole picture. Everything else is a detail, an optimization, or a special case.

Here is a tiny program with all four in it.

x = 17
y = x * x
print(f"{x=} and {y=}")

x=17 and y=289

The multiplication happened in the processor. The values of x and y were sitting in memory. The text of the program itself was read off of storage before anything ran. The line you are reading now came out through an output device.

The Processor

The processor, also called the CPU (central processing unit), is the part that actually computes. Its job description is short and boring. Fetch an instruction. Do it. Repeat. This is called the fetch-execute cycle, and a modern processor runs through it a few billion times per second.

The instructions are far smaller than the lines of Python you write. They are things like "add these two numbers", "copy this value over there", and "if that number is zero, jump to a different instruction". A single line of your Python code turns into many of them.

The processor also has a very small amount of storage of its own, called registers. A register holds one number that the processor is working with at this instant. There are only a few dozen of them.

Key Idea: The processor is unbelievably fast and unbelievably stupid. It does exactly what it is told, one small step at a time, and it has no idea what any of it means.

Memory

Memory, usually called RAM, is where a running program keeps everything it is currently using. Every variable you assign lives in memory. So does the program itself while it runs.

RAM stands for random access memory. The random access part means the processor can jump straight to any location it wants, at the same speed, without reading through everything in front of it. Memory is one gigantic numbered list of slots, and the number of a slot is called its address.

The important word for memory is volatile. When the power goes out, memory forgets. When your program ends, its memory is handed back to the operating system and the values are gone. This is why closing a program without saving loses your work.

Storage

Storage is the part that remembers. Hard drives, solid state drives (SSDs), USB sticks, and SD cards are all storage. The word for this is non-volatile, which just means it survives losing power.

Storage is organized into files and directories, which is the world you learned to walk around in from the terminal. Saving means copying from memory into storage. Opening means copying from storage into memory.

import tempfile, os

path = os.path.join(tempfile.gettempdir(), "architecture_demo.txt")

with open(path, "w") as f:
    f.write("This sentence is now on a disk.")

with open(path) as f:
    print(f.read())

This sentence is now on a disk.

You do not need to understand that code yet. We will come back to reading and writing files later. For now, notice what it shows. The sentence went out to storage and came back. Unlike a variable, it will still be there tomorrow.

Input and Output

I/O is everything that connects the computer to something outside itself. The keyboard, mouse, microphone, and camera are inputs. The screen, speakers, and printer are outputs. The network card is both.

You have already used both sides. The print function is output, see strings_and_print. The input function is, unsurprisingly, input, see input_and_fstrings.

Storage counts as I/O too, which is why the four parts overlap a little. The processor talks to a disk in much the same way it talks to a keyboard. It is all data coming in and going out.

Why We Keep Them Separate

You might reasonably ask why we bother with both memory and storage. Why not keep everything in the one that remembers?

The answer is speed. Each step away from the processor is enormously slower than the one before it. The numbers are so lopsided that they are hard to feel, so let's stretch them out. Suppose grabbing a number from a register took one full second.

memory = 100            # nanoseconds, roughly
ssd = 100000
hard_disk = 10000000

print("If reading a register took 1 second, then...")
print(f"reading from memory would take about {memory} seconds.")
print(f"reading from an SSD would take about {ssd / 3600:.0f} hours.")
print(f"reading from a spinning hard disk would take about {hard_disk / 86400:.0f} days.")

If reading a register took 1 second, then...
reading from memory would take about 100 seconds.
reading from an SSD would take about 28 hours.
reading from a spinning hard disk would take about 116 days.

That is the trade-off. Fast things are small, expensive, and forgetful. Slow things are big, cheap, and permanent. A computer is an arrangement for keeping the data you need soonest in the fastest place you can afford.

This pattern repeats inside the machine. Between the registers and the memory there are two or three levels of cache, which are small pools of very fast memory holding recent values, just in case you want them again.

Running a Program

Now we can say what actually happens when you run python hello.py.

  1. The operating system finds hello.py in storage.
  2. It copies the contents into memory.
  3. The processor starts fetching and executing instructions out of memory.
  4. Those instructions move values between registers and memory, and hand text to an output device.
  5. The program ends, and its memory is released.

Notice step 3 carefully. The instructions being executed are themselves just numbers sitting in memory, right alongside the data.

Key Idea: A program is data. The machine does not distinguish between the recipe and the ingredients. Both are numbers in memory.

That last idea is the one that makes general-purpose computers possible. It is also very old. When Babbage designed the Analytical Engine in the 1830s, he called his memory the Store and his processor the Mill, and he fed both instructions and numbers in on punched cards. The names changed. The design did not.

A Word About Words

People use these words loosely, and it causes real confusion.

When a phone says it is "out of memory", it usually means storage. When a website says "in the cloud", it means storage and processors in somebody else's building. A "64 GB" phone is describing storage, while "8 GB of RAM" is describing memory.

When you are reading about computers, it is worth pausing to ask which one is meant.

The essay existed only in memory, which is volatile. Nothing had been copied into storage yet, so nothing survived the power loss.

Exercise 3. Your friend says a computer would be simpler if it just had one kind of place to put things, instead of both memory and storage. Give the strongest argument you can for their side, then say why we do it the other way anyway.

Click to reveal.

The argument for one kind of place is a good one. You would never lose unsaved work, there would be no saving and loading, and there would be one set of rules instead of two. We do it the other way because the storage that remembers is thousands of times slower than the memory that forgets. A processor fed only by storage would spend nearly all of its time waiting.
