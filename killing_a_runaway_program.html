Killing a Runaway Program

Sooner or later, you will start a program that does not stop. Maybe it has a loop with no way out. Maybe it is waiting for input that will never come. The terminal just sits there ignoring you, and it starts to feel like the computer has been taken hostage. It hasn't. Here are your options, from polite to brutal.

Here is a program that will not stop on its own.

while True:
    name = input("Who's there? ")
    print(f"Hi, {name}.")

There is no break in that loop, so nothing inside the program will ever end it. It has to be stopped from the outside.

Interrupt with Ctrl-C

Hold down the Control key and press c. On a Mac, that is Control, not Command.

This sends an interrupt to the running program. Python turns that interrupt into an error called KeyboardInterrupt. If nothing catches it, the program stops and you get a traceback that ends like this.

Traceback (most recent call last):
  File "greet.py", line 2, in <module>
    name = input("Who's there? ")
KeyboardInterrupt

That traceback is not a bug. It's a receipt.

When Ctrl-C Does Not Work

while True:
    try:
        age = int(input("Age? "))
        print(f"You are {age}.")
    except:
        print("That's not a number.  Try again.")

Press Ctrl-C on that program and it prints That's not a number. Try again. and keeps going. The KeyboardInterrupt was raised inside the try block, and the bare except: catches everything, including your attempt to quit. The fix is to name the error you actually expected.

    except ValueError:
        print("That's not a number.  Try again.")

I have found that a bare except: causes more trouble than it saves. Say what you mean to catch.

End the Input with Ctrl-D

Press Ctrl-D at the prompt. That signals end of file, which is the terminal's way of saying there is no more input coming, ever. The input function (see input_and_fstrings) responds by raising EOFError. That is a different error from KeyboardInterrupt, so it often slips past a handler that was swallowing your Ctrl-C.

In Git Bash on Windows, Ctrl-D usually works too (see git_bash_getting_started). In the plain Windows Command Prompt, end of file is Ctrl-Z followed by enter, which is unfortunate, because Ctrl-Z means something completely different on a Mac. That's the next section.

The Bigger Hammers

Ctrl-\ (Control and backslash) sends a quit signal. Python does not hand this one to your code as a catchable error, so the program dies where it stands. You may see a message about a core dump. That's fine.

Ctrl-Z suspends the program and gives you your shell back. Be careful with this one. The program is not dead, it is parked, still holding everything it had. Follow it with kill %1 unless you plan to go back to it with fg.

jobs
kill %1
fg

jobs lists the programs you have parked, kill %1 finishes off the first one, and fg brings it back to the foreground.

Key Idea: Ctrl-C asks your program to stop, and a program is allowed to refuse. Ctrl-\ and kill -9 do not ask.

Kill It from Another Terminal

Every running program has a process id, a number the operating system uses to keep track of it. Open a second terminal (see navigating_the_file_system) and look for your program.

ps

You'll get a short table, and one of the rows will be your Python program. The number in the PID column is the one you want.

kill 51342

Plain kill is a request, much like Ctrl-C. If the program ignores it, stop asking.

kill -9 51342

The -9 cannot be caught, blocked, or ignored by the program. It is the end.

If you know the file name and don't feel like reading a table, this does the search and the kill in one step.

pkill -f greet.py

Closing the terminal window kills whatever is running inside it, so that works too. It's just the blunt instrument, and I'd rather you knew the others first.
